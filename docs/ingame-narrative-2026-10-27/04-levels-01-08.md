# Midnight Menagerie level scripts 01 through 08

Status: authored game narrative proposal, revision 5 after structural, comedy/cross-review, regression and whole-game integration passes. Detailed round records preserve what each reviewer actually read. No game code, art, balance, or save data has been changed. These are eight region packages, not eight sequential stages. Region numbering follows the source catalogue; a run can encounter these in another order or miss them entirely.

## Source and delivery contract

Audited sources: `CONTRACTS.md`; `game/src/state/mapgen.js` (authored room names and region bosses); `game/src/state/run.js` (`wingOffer`, `completeRegion`, `_heldTarget`, `rescueCompanion`); `game/src/data/schema.js` (pronouns, Companions, terms); the eight matching `docs/design/regions/01–08` chapters; the eight matching `game/src/data/bosses` modules; `game/src/scenes/event.js` and `event.css`; `game/src/combat/engine.js` (`say` emits a log event).

Implementation findings: the expedition normally has six wings. The initial entry is the Foyer; surveyed entry options become available through progression. Later wings are selected during the expedition, and the last crossing is to the Heart. The region numbers below do not imply visit order. The current build persists mapped/cleared wings and Companion rescues. Each wing holds at most one missing Companion for that run; the Rescue room and boss do not each award a different one. The Heart holds none. A region's usual Companion is not proof of tonight's captive. Missing pets are a separate narrative system.

The Carnivorous Conservatory is the Greenhouse boss; the Head Gardener is a Big Scare. Pudding is the current Graveyard Companion association in schema/map data, despite older prose naming Mossbit. No script here requires either to be present.

The Curiosity screen supports scrolling prose and full-width choice buttons. Its page width is `min(780px, 100%)`; it is not a fixed character-count dialogue box. No tested line limit is claimed. Boss modules support action tells and rule descriptions. `c.say` emits `EV.LOG`, but the combat renderer does not consume that event for a readable bark display. Every BT log line therefore requires **D-BARK**, a new display consumer and verification, not just replacement text. No existing reusable post-boss dialogue, clue journal or narrative persistence layer was verified. All additions below require content integration; persistent variants require additional state. No live UI or child playtest has been performed.

## Unit metadata inherited by every script

Every bold unit ID below is stable. The following defaults are part of each unit's complete specification; local overrides replace them.

* **Canon:** NEW dialogue/proposed staging grounded in the cited region's existing motifs; no newly invented founder, dead family or historical incident becomes canon. Object inscriptions are newly proposed evidence, not quotations from the existing build.
* **Speakers:** labeled lines only. Narration is visible prose. A named Kid speaks only when that Kid is in the active party; otherwise use the exact adjacent `Absent` line as narration. Optional Companion reactions require that Companion in the active party, not merely unlocked. Animals do not acquire human speech here.
* **Visual direction:** use the existing room backdrop and text page. All physical business is fully conveyed by prose. Animated staging is optional future work; no camera move, new rig, color-only signal, audio-only clue or timed choice is required.
* **Existing reads:** current region, authored room identity, party Kid/Companion identities, current boss identity and resolved encounter result. Post-boss code must use the actual `_heldTarget`/rescue result, not the chapter's nominal Companion.
* **Proposed reads/writes:** `N.seen[unitId]`, `N.clues[unitId]`, `N.bossMet[region]`, `N.bossResolved[region]` persist per profile; `N.runPlayed[unitId]` resets on a new expedition. These are design names, not existing fields. N.seen means full scene OR delivered core recap; optional N.fullRead records full-text reading only if a journal needs that distinction. Completing an optional clue writes only the evidence actually shown; leaving it unread writes neither clue nor seen. First boss encounter writes bossMet after full or short entry delivery; confirmed victory plus delivered P scene or P recap writes bossResolved. A later win with bossResolved uses P repeat; `Read again` offers full text without automatically forcing it. Do not mark a rescue, cure, permanent door unlock or historical truth from a seen flag.
* **First/repeat:** first means this profile has not read the unit, regardless of whether the fight has been won before. Long content appears once; repeats use the supplied short form, with `Read again` available only if the proposed journal/replay UI is implemented. For older saves with a cleared wing but no N fields, use neutral short scenes on entry and offer the first scene as an explicitly labeled replay; do not assert a forgotten conversion happened. In co-op use per-seat seen state; shared narration never asserts all players saw an optional clue. At most one optional character exchange per room; no banter during card targeting. Repeat battle bark at most once per encounter and once per three expeditions per profile; do not delay combat for it.
* **Fallback:** without narrative state, use the short, state-neutral repeat/recap text on every visit. Without a dialogue screen, put that short text in the existing Curiosity prose or appropriate authored event outcome with minimal content wiring. This still requires an approved integration edit and has not been implemented. If no safe display exists, omit optional barks; never hide mechanics in them.

Types give the remaining fields:

| Type | Trigger and prerequisites | Choices and consequences | Skip and recap | Reading estimate and fallback |
|---|---|---|---|---|
| F foreshadow | First entry to its named room, when that room is reachable; before boss if possible; otherwise omit | `Continue` only; no gameplay effect | The repeat line is the recap | 15–30 seconds; optional repeat can be region intro prose with neutral backdrop, never claim an unvisited room was reached |
| C clue | Inspect named authored room when reachable; optional, no prior clue required | `Look closer` displays quoted text; `Keep going` returns without cost or clue flag | Skipping loses only optional detail; the region P recap supplies essential inference | 20–42 seconds; use repeat if no inspection support |
| B encounter | Before this region's actual boss fight; combat has not started | `Begin Scuffle`; optional `Skip scene` goes to identical fight | B repeat is complete encounter recap | 20–39 seconds; put repeat in boss intro prose |
| BT battle | Exact cited existing action/log emission hook; D-BARK consumer required; no extra enemy action | No narrative choice or mechanical change | Optional; move intent/rules remain visible and authoritative | Short optional text; user-readable D-BARK presentation required, otherwise omit |
| P resolution | Confirmed boss victory only, after rewards have resolved and before route selection; never on defeat, retreat or reconnect without result | `Continue`; optional `Skip scene`; neither changes victory or rescue results | P recap displayed even when scene skipped; proposal for mandatory short recap | 30–60 seconds; use P recap in reward/route prose |
| T transition | At actual route-selection interface after the region; no assumed destination | Existing available route choices/votes only; no new route or false unanimity | Exact line doubles as recap | 5–10 seconds; existing atlas explanatory prose |

Proposed recaps are essential-route delivery, not implemented guarantees. If a player bypasses the entire wing, the Heart must independently establish care, blocked departure and the Keeper's responsibility; these wings enrich those truths rather than unlock the only explanation.

Integration repeat guard: after N.bossResolved, use B repeat even if the full B was skipped earlier. Do not re-stage a physical clue that contradicts that guardian's specific local change (for example L03-C3's cut inside cord after L03-P repairs it). Such evidence can be reread only as an explicitly dated earlier journal entry if actually recorded; otherwise suppress it. Required facts remain available at the Heart. A local promise is preserved, not excused by an invented room reset. The neutral repeat challenge concerns the current Scuffle, not renewed captivity of a freed resident.
